# スライド先生 MVP プラン（2026-09-30）

## 0. 前提と制約

- **Python はターミナルで使えない** → `main.py` / `start.command` は現環境では動かせない
- 使えるもの: Google Chrome / Safari、Microsoft PowerPoint、`swiftc`（Command Line Tools）
- まずは **Gemini を使わず** に、画面収録と「画面変化の検知」が成立するかを確かめる

→ MVP は **ブラウザ（Chrome）で HTML を開くだけで動く形** を本線にする。
  ネイティブ化（Swift）は MVP 後に回す。

## 1. 現状チェック結果

### 1.1 プロダクトが 3 つに分裂している

| 場所 | 名前 | 対象アプリ | AI | 状態 |
|---|---|---|---|---|
| `docs/*.md`, `prototype/index.html` | 操作ナビ | Photoshop | ローカルAI（クラウド禁止） | 仕様書 + UIモックのみ |
| `main.py`, `prototype/slide-sensei.html`, `README.md` | スライド先生 | PowerPoint | Gemini | 動く試作（最新） |
| `Extension/` | AI Screen Guide | Blender/UE/Photoshop | Gemini | Chrome拡張の試作 |

`docs/MVP_SPECIFICATION.md` は「Photoshop・ローカルAI・矢印なし・クラウドAI禁止」だが、
最新コードは「PowerPoint・Gemini・矢印あり」で**正反対**。
本プランでは最新の **スライド先生（PowerPoint）** を MVP 対象に統一する。

### 1.2 `main.py`（ネイティブ試作）の問題

- README と実装が不一致: README は `customtkinter` / `mss` / `google-generativeai` を前提にし
  `start.command` も pip install するが、`main.py` は標準ライブラリのみ。また「長辺1024pxに縮小」と書いてあるが実装は**未縮小**（Retina だと数MB送信）
- 変化検知が JPEG バイト列の完全一致のみ（`bytes_similar`、`sample_step` 未使用）→ カーソル点滅だけで毎回 AI 呼び出し
- AI が「ステップ完了」と判定して次に進んでも `force_analyze` を立てないため、**画面が動くまで次の案内が出ない**
- PowerPoint が最前面でないと停止する設計なのに、案内窓のボタンを押すと案内窓が最前面になる → 「PowerPointをフォアグラウンドに…」で止まりやすい
- `System Events` 経由のウインドウ取得にアクセシビリティ/オートメーション許可が要るが README に記載なし
- キャプチャ範囲に自アプリの案内窓・赤枠オーバーレイが写り込む（AI が自分の矢印を見る）
- `confidence` を受け取るのに使っていない（低信頼でもステップが進む）
- API キーを URL クエリで送っている（ヘッダ `x-goog-api-key` 推奨）
- モデル `gemini-2.0-flash` は提供終了予定/終了済みの可能性あり（要確認）

### 1.3 `prototype/slide-sensei.html`（ブラウザ試作）の問題

- 変化検知が dataURL のサンプリングハッシュ → マウスを少し動かすだけで「変化あり」
- AI 応答の `guidance` / `hint` をエスケープせず `innerHTML` に入れている
- 解析のたびにメッセージが追加され、チャット欄がすぐ埋まる
- ステップ完了後に `lastFrameHash` を消さないので、次ステップの案内が画面変化待ちになる（main.py と同じ）
- 案内がブラウザ内プレビューにしか出ないので、PowerPoint を触りながら見るには窓を並べる必要がある

### 1.4 `Extension/` の問題

- `background.js` の `requestDesktopCapture` はどこからも呼ばれていない（デッドコード）
- 変化検知なしで 6 秒ごとに必ず API 呼び出し → 無料枠をすぐ消費
- `intervalSec` が文字列のまま `setInterval` に渡る、履歴が実質 1 往復のみ

## 2. 方針

1. **ブラウザ1ファイル構成**（`prototype/slide-sensei.html` を育てる）。インストール不要・Python不要
2. **AI は差し替え式**。`GuideEngine` インターフェースを切り、
   - `ManualEngine`（AIなし・手動「次へ」＋変化検知）
   - `OcrEngine`（任意: tesseract.js で文字を読んで完了判定）
   - `GeminiEngine`（最後に接続）
   の順に実装する
3. 案内は **Document Picture-in-Picture**（Chrome 116+）で**常に最前面の小窓**に出す。
   PowerPoint の上に重ねて使える
4. ネイティブ版（Swift + ScreenCaptureKit）は MVP 合格後に判断

`prototype/capture-test.html` を Chrome で開く。

- [ ] PowerPoint ウインドウを選んで共有できる

**ここで決める数値**: 取得間隔（秒）、変化閾値（%）、送信サイズ（長辺 px）

#### 実機計測（2026-09-30、PowerPoint 実画面）

| 操作 | 変化量 |
|---|---|
| 文字入力（ウインドウ半分） | 約 0.17% |
| 文字入力（ウインドウ大） | 0.5〜0.8% |
| クリック | 0.17〜1.5%（カーソル・虫眼鏡などの表示で大きくぶれる） |
| 新しいスライド | 約 5% |
| 大きなレイアウト変更 | 約 35% |

結論:
- クリックのノイズ（〜1.5%）と文字入力（0.17〜0.8%）の範囲が重なるので、**閾値1つでは区別できない**
- 変化検知は「見に行くきっかけ」に使うだけにする。閾値は低め（0.15%）にし、
  **「動きが止まってから、前回の確定画面と比べる」**（capture-test.html に実装済み）
- 大きさで3段階に分ける: 小 <3%（入力・クリック）／中 3〜20%（新しいスライド・メニュー）／大 ≥20%（レイアウト変更）
- 実機で「カーソルを動かすだけで変化中になる」問題 → 判定を次のように変更（両ページに反映済み）
  - 縮小グリッドを 64×36 → **192×108** に（64×36 ではタイトル1行とカーソルが同じ大きさに見えた）
  - つながった変化の塊が **14マス以下ならカーソルとして無視**（capture-test のスライダーで調整可）
  - 「落ち着いた」の判定を、前回サンプルとの差ではなく **確定画面との差の増減 < 0.05%** に
  - 変化ありの閾値は 0.05%（カーソルを除外したので下げられる）
  - 擬似テスト: カーソル移動（2倍サイズでも）0.00%、タイトル入力 0.41%、入力中は「変化中」→止めると「できた？」
- ステップが完了したかどうかは %では決めない。Phase 1 は「できた」ボタン、Phase 2 は文字認識、Phase 3 は AI で判定する

### Phase 3: AI 接続（無料）✅ 2026-10-07

調査（2026-10 時点）:
- Chrome 内蔵AI（Prompt API / Gemini Nano）は Chrome 148（2026-05）で既定で有効、画像入力あり、日本語は 149 から。
  モデル約3〜4GB、空き容量 20GB、GPU 4GB または メモリ 15GB 以上などの条件
- Gemini API 無料枠: `gemini-3.8-flash` などが無料。**無料枠の送信内容は Google の製品改善に使われる**。
  `gemini-2.0-flash` / `2.5-flash` は提供終了・新規利用不可（旧試作の main.py / 拡張機能はそのままでは動かない）

実装:
- [x] 方式を選べる: 使わない / Chrome 内蔵AI / Gemini API 無料枠（APIキーはヘッダ送信、localStorage に保存）
- [x] 🤖 AIに聞く: 画面＋手順を渡し、`{done, say, target, box, reason}` を JSON で受け取る。
  **位置は AI の答えたボタン名を文字認識で探して決める**（AI は位置が不正確なため）。見つからなければ AI の推定範囲（0〜1000）を使う
- [x] 「できた？」にひとこと: 文字の完了条件がない手順でだけ AI に判定させ、確認は人に残す
- [x] ✨ 手順を作る: やりたいこと → AI がレッスン（3〜8手順、押す場所の文字、新しく現れる文字）を作る。
  完了条件は `appearsNew`（ステップ開始時になかった文字が現れた）にして、最初から見えている文字で誤って進まないように
- [x] 呼び出し制限（4秒に1回・1分に8回）、429 などのエラーは日本語で表示
- [x] 偽の AI（内蔵AI・Gemini の両方）で動作確認。**本物の AI ではまだ未確認**
- [ ] 実機で各方式の応答時間と、「AIに聞く」の正答率（光らせた場所が正しいか）を測る

### Phase 3.5: AI を主役に —「🧭 AIにおまかせ」（どのソフトでも）✅ 2026-10-07

実機の感想「AI を使ってもガバガバ・AI を使う優位性がない」への対応。原因の分析:
1. AI が決まったレッスンの「おまけ」だった（手順はレッスンが決め、AI は横からひとこと）→ 文字認識だけで足りてしまう
2. 場所を AI に画像から「名前で当てさせて」いた → 小さいモデルは画面にない名前や位置を作りがち
3. AI が自分の指示を確かめていなかった

変更:
- [x] **おまかせモード**: やりたいこと → AI が画面を見て次の一手を1つ出す → 画面が変わったら AI が「できたか」を確かめて次へ
  （判断できないときは「できた？」で人に聞く）。レッスンを作らずに、どのソフトでも案内できる＝AI を使う理由
- [x] **Set-of-Mark**: 文字認識の単語を行ごとにまとめた番号札（最大80）を画像に描き込み、一覧と一緒に渡して番号を選ばせる。
  位置は文字認識の値を使う。番号札のない場所だけ AI の推定範囲（0〜1000）
- [x] 1回の呼び出しで「前の手順ができたか」と「次の一手」を同時に答えさせる（無料枠の回数を節約。1操作＝1呼び出し）
- [x] 暗い画面のソフト対応: 48px 区画ごとに明暗を判定（平均150未満かつ白っぽい点20%未満なら暗い背景）し、
  暗い区画は「平均より50明るい部分」を文字にする。単純な反転は赤いタイトルバーを黒く潰し、近くの行まで読み落とした
- [x] 変化検知: 小さな塊が4つ以上同時に出たら本当の変化として数える（リボンのタブ切替が「カーソル」扱いで消えていた）
- [x] 「✨ 手順を作る」（AI が前もってレッスンを作る）は効果が薄かったので廃止し、おまかせに置き換え
- [x] 偽の AI で確認: 開始 → 挿入タブ（0.20% の変化を検知）→ 表 → 完了。カーソル・文字カーソルの点滅だけでは AI を呼ばない。AI 呼び出しは3回
- [ ] 本物の AI（Gemini 3.8 Flash / 3.5 Flash-Lite / 内蔵AI）で、PowerPoint 以外（Excel・Premiere など）も含めて正答率を測る

### D. AI を足す（C と並行可）
- 「〇〇したい」と入力すると、AI が手順（レッスン）を組み立て、既存のハイライト・判定エンジンで案内する
- 文字では判定できないステップ（色・配置・テーマ）だけ、画像を AI に見せて判定
- 組織導入向けに「画像を外部に送らない」モード（端末内のモデル、または送信前に同意を取る）を用意

### E. 効果の検証（いつでも）
- 対象ユーザー（PowerPoint 初心者 5〜10人）で「あり / なし」を比べる: 完了率・所要時間・つまずき回数
- 使いやすさアンケート（SUS など）と自由記述 → 改善点の優先順位づけ
